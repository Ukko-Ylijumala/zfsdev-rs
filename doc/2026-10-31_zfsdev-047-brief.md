# zfsdev v0.4.7: `set_fsacl` permission-set keys (pass 6 T3, delegations)

## The bug

`ioctl.rs::set_fsacl` (~line 2280) and `deleg_whokey` (~line 623) only produce
the *base* who-key `<type><inherit>$<id>` (lowercase `u`/`g`/`e`). ZFS keeps
permission-set grants (`zfs allow user @myset fs`) under a separate key whose
type char is uppercase: `U`/`G`/`E`. So two things go wrong:

1. **An `A` grant of `@set` does nothing.** The `@set` name goes into the
   lowercase key's perm nvlist. The kernel only expands sets found under the
   `*_SETS` keys (dsl_deleg.c `dsl_load_user_sets`, called with
   ZFS_DELEG_USER_SETS / GROUP_SETS / EVERYONE_SETS), so the grant is stored
   but never takes effect.
2. **A whole-who revoke (`perms` empty, `unset = true`) leaves the who's set
   grants behind.** Only `ul$<id>` / `ud$<id>` get boolean flags. libzfs also
   flags `Ul$<id>` / `Ud$<id>`.

## Reference: libzfs (cmd/zfs/zfs_main.c @ 2.2.2, `store_allow_perm`)

- Split `perms`: names starting with `@` go to `set_nvl`, the rest to `base_nvl`.
- For each locality in `['l', 'd']` (local / descendent):
  - if `base_nvl` is non-empty, add `"<base_type><loc>$<who>"` → base_nvl
  - if `set_nvl` is non-empty, add `"<set_type><loc>$<who>"` → set_nvl
- With no perms at all (whole-who unallow), for each locality add a **boolean**
  under BOTH `"<base_type><loc>$<who>"` and `"<set_type><loc>$<who>"`.
- Type pairs (zfs_deleg.h): user `u`/`U`, group `g`/`G`, everyone `e`/`E`
  (`e<loc>$` with an empty id), create `c`/`C` and named set `s`/`S` (these
  last two use locality `ZFS_DELEG_NA` = `-`, not l/d).

## Requested changes

- `deleg_whokey(who, inherit, sets: bool)` (or a sibling fn) that picks the
  uppercase type char for set keys; keep the existing output for `sets = false`.
- `set_fsacl`: split `perms` on a leading `@`, then emit base and/or set keys
  per locality as above. A whole-who revoke flags both keys per locality.
  Keep the existing refusal of an empty *grant* (`ZfsError::Invalid`).
- Unit tests against the packed nvlist (or a pre-pack builder):
  `[@a, create]` grant → `ul$1000={create}`, `ud$1000={create}`,
  `Ul$1000={@a}`, `Ud$1000={@a}`; whole-who revoke → four boolean keys;
  Everyone → `el$`, `El$`, …
- Optional but useful app-side: a public who-key decoder (type char →
  {User, Group, Everyone, Create, NamedSet} × is_set × locality × id) so the
  browser's `deleg_who_decode` can show and revoke set grants. Today it
  ignores the uppercase keys (T3 node.rs item, which I'll handle app-side once
  0.4.7 lands).
- Canary: the existing `live_zfs.rs` deleg canary against a bogus pool still
  passes (ENOENT first). If the delegated playground exists, a round-trip of
  `zfs allow -s @t create` + grant `@t` + `zfs allow` listing shows it under
  `U`.
